ChangeHow it rendersCost
PR # column New leftmost column, one cell per item row, blank on heading and terminator rows. Resolve source_pr_item_id → PurchaseRequestItem → PurchaseRequest.pr_number in the view. No migration.
Remark as heading The description column emits the remark on a heading row and blank on item rows; all other columns emit a blank spacer on heading rows. Reverses the template's documented “no heading rows” rule. Alignment still holds by construction — every stack keeps one cell per row.
- NOTHING FOLLOWS - One extra row after the last item, text in the description column, blank elsewhere. Smallest of the four. No layout maths.
PHP on the total Currency code printed to the left of total_amount. New PurchaseOrder.currency, String(3), NOT NULL, default 'PHP' + migration. Label only — the amount is still booked in PHP.

4 · Decisions this mockup is asking you to confirm

QuestionWhat I have assumed
Where the heading sits At the product column's x (92), with items indented to 112 — matching your arrow on the annotated print. This is a designer position, not hardcoded: the description column can be dragged anywhere afterwards without a code change.
PR # vs the # column Both columns exist; PR # takes x=56 and the line-number column is hidden, since your legacy pad has no line counter. Reversible in the designer.
PR number format Prints CAS's own pr_number. Your legacy numbers read 25-0914; CAS issues 00001. The printed value will not look like the old pad.
Terminator wording Exactly - NOTHING FOLLOWS -, hyphens and spacing as on PO 00984.
Currency placement To the left of the total, as on the legacy pad. Prints for every PO including PHP ones — not suppressed when it is the default.

Separately, and needing no code: philgen's saved layout has quantity only 20 px wide, and line_number (x 111–141) overlapping product (x 94–294). Both are fixable in the layout designer.
